# تحضير ترحيل المجموعات

يبقى إثبات تعافي المزوّد وسجل ترحيلات الإنتاج شرطًا للنشر. أصلح هذا العمل خطر أداة محلية واختبر فصل المخطط عن نقل البيانات. **لم تُصلح أو تُفعّل به سلسلة الإنتاج.** بقيت ملفات SQL واللقطات وسجل الترحيلات مطابقة لبصماتها السابقة.

## ما نُفذ

كانت `scripts/sync-migration-snapshots.mjs` تعيد توليد معرّفات لقطات موجودة. أصبحت الآن تفحص السجل وتسلسل اللقطات ومطابقة مخطط Drizzle دون كتابة. يعمل الاستدعاء العادي أو `--check` كفحص فقط، وترفض معاملات إعادة التوليد. التغييرات المستقبلية تحتاج ترحيلًا جديدًا مضافًا بدل إعادة إنشاء التاريخ.

توفر `scripts/collection-rollout.mjs` عمليتين منفصلتين دون عميل شبكة أو ربط إنتاج أو أمر تطبيق أو تعديل إعداد الاستضافة:

- `schemaOnlyProposal(root)`: يقرأ SQL ويعيد مقترحًا في الذاكرة يفصل عملية نقل المجموعات المراجعة من0004، ويرفض تعليمات غير مراجعة. تبقى حالته proposal-only، ولا يثبت صلاحية نشر أو تعافٍ أو سجل مزوّد. لا يكتب إلى drizzle أو خرج البناء.
- `collectionBackfillPage(database, cursor, limit)`: يقرأ نطاقًا مفهرسًا من المعرّفات بحد100 عنصر للدفعة، ويطبق سجلات المجموعات بدفعة معاملات واحدة. يعيد تقدمًا قابلًا للحفظ؛ يجب على المستدعي حفظه بعد النجاح. تجعل المعرّفات الحتمية إعادة المحاولة آمنة، وتُحفظ أسماء المجموعات العربية والمسافات والطوابع الزمنية. لا يطمس مجموعة مستقلة موجودة، ولا يحدّث أو يحذف عناصر المكتبة.

العملية مخصصة لتجربة نسخة مجمدة ومعزولة. لا يجعل المؤشر أو أكبر معرّف المصدر الحي ثابتًا، ولا يضمن التقاط تعديلات أو معرّفات جديدة متزامنة. لا توجد نقطة API تستدعيها، ولا تمثل إذنًا لتشغيلها على الإنتاج. تُلغى الدفعة الفاشلة ذريًا، ويمكن إعادة دفعة نجحت قبل فقدان حفظ التقدم.

## الاختبارات

أصبح العدد20 مجموعة. يرقّي الاختبار الجديد عينة قديمة من10,000 عنصر بالمخطط المنفصل، وينقل المجموعات بدفعات37 عنصرًا. يفحص كل قيم الأعمدة القديمة، وتجميع المالك والاسم والطوابع الزمنية، ويحفظ لون وأيقونة وأب ومراجعة المجموعة الموجودة. يجرب الفشل وسط الدفعة والاستئناف من مؤشر محفوظ وإعادة دفعة ناجحة وإعادة العملية كاملة، وحدود المعاملات واستخدام فهرس النطاق. لم تتغير أي بصمة SQL أو لقطة أو سجل بعد استدعاءات الفحص أو محاولة إعادة التوليد المرفوضة.

نجحت أيضًا تجربة D1 فعلية محلية منفصلة مع231 عنصرًا اصطناعيًا: ثماني دفعات31 عنصرًا، وإعادة متزامنة للدفعة الأولى، وتطابق التواريخ وبصمات العناصر. أُعيد بناء المصدر الأصلي كتطبيق اختبار محصور في localhost؛ نجحت15 حالة عزل واختبارات الدخول وتعديل المقال والمكتبة ورفع/تنزيل بايتات الملف والخروج على D1/R2 المحلي. هذه اختبارات تنفيذية بلا واجهة، ولا تثبت قبول الواجهة أو المحدّث المثبت أو الإنتاج. لم يُشغّل الملف التنفيذي الإنتاجي.

## ما يلزم من المزوّد

ما زال البناء يضم مجلد drizzle التاريخي، وفيه نقل البيانات داخل0004. **لا تنشره اعتمادًا على نجاح المقترح المنفصل.** يلزم معرفة سجل الاستضافة الحقيقي وإثبات أن الترحيل المراد إصلاحه لم يطبق هناك مطلقًا، بما في ذلك حالات فشل النشر الجزئي. إذا كانت حالته مجهولة أو مطبقة، لا تُعدّل SQL أو بياناته التاريخية. يجب تأكيد مسار إصلاح أو إضافة أو أساس مخطط تدعمه المنصة، ثم اختبار نفس المصدر والحزمة على نسخة معزولة مستعادة قبل النشر.

تبقى النسخة الكاملة المقترنة من D1/R2 وتخزينها الخاص المستقل وتجربة استعادتها مطلوبة؛ راجع [قرار النشر](deployment-safety.ar.md) و[طلب المزوّد](provider-recovery-request.md). لا تكفي الشفرة أو عرض قاعدة محدود أو نسخة حساب واحد. قد تكشف إعدادات الإدارة المصادق عليها قدرات لا يعرضها الموصل، ولذلك لا نستنتج غياب نسخ داخلية لدى المزوّد.

## العملاء والنشر

ما زالت مقارنة1.5.3 الأصلية ترفض عرض1.0.0 العددي وتقبل ترتيب التحديث2.0.0، مع بقاء هوية المنتج1.0.0. تعمل الجلسات وقراءة الروابط والملفات في الاختبارات المعزولة، وتُرفض PATCH/DELETE بلا مراجعة428 لحماية البيانات، ويعطي التعديلان الحديثان المتزامنان200/409. هذا ليس توافق كتابة شفافًا؛ يلزم انتقال منسق للعملاء. لا يعوّض رأس إصدار أو تخمين مراجعة آخر قراءة اللقطة القديمة التي لم يرسلها العميل.

لم تُطبق ترحيلات أو يُنشر الإنتاج أو تُفعّل حالة إيقاف الكتابة أو وسم Stable أو حزمة Windows أو بيانات تنزيل وتحديث. يلزم اجتياز بوابات التعافي والترحيل وانتقال العملاء وسعة الاستعادة وقبول Windows قبل ذلك.

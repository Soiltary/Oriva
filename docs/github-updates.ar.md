# الانتقال إلى توزيع التحديث عبر GitHub

[English](github-updates.md)

لا يحتوي أرشيف Sites18 أسماء EXE الجديدة1.0.0 و2.0.0 أو بياناتv2. تعيد المسارات الجديدة404 بينما تعيد البيانات القديمة1.5.3 الرمز200. السبب محتوى نشر غير موجود، وليس دليلًا على منع Sites لمسارات الملفات التنفيذية. يبقى الموقع وAPI المنشوران دون تغيير.

يمكن للإصدار العام الأول اعتماد مستودع `Soiltary/Oriva` الحالي مرجعًا للتحديث. توثق GitHub بيانات الإصدار وبصمة الأصل، وقد يعيد التنزيل200 أو302 ([بيانات الإصدار](https://docs.github.com/en/rest/releases/releases)، [الأصول](https://docs.github.com/en/rest/releases/assets)). يستخدم التنفيذ اتصال WinHTTP مستقلًا ومجهولًا، وليس اتصال API Oriva الذي يحمل الجلسة.

يفحص التطبيق المنشور آخر إصدار Stable منشور فقط. يلزم أصل واحد بالضبط باسم `windows-update.json` وآخر باسم `Oriva.exe` بحالةuploaded، مع الحجم وSHA-256 وعناوين API القياسية للمستودع نفسه. تُفحص بصمة ملف البيانات قبل قراءته؛ ويربط رقم المنتج بوسم الإصدار وحجم وبصمة الملف التنفيذي. قيمةschemaVersion هي1، ويحتفظ updateVersion الصريح بترتيب2.0.0 للمنتج1.0.0. يُرفض خفض رقم المنتج أو ترتيب التحديث.

يُسمح بـHTTPS على443 فقط، مع تعطيل التحويلات التلقائية والكوكيز والمصادقة التلقائية. يُقبل تحويل302 واحد مفحوص من API الأصل إلى مضيف CDN GitHub المحدد ومسار معرّف المستودع. تُرفض المضيفات والمنافذ والمسارات الأخرى وHTTP والتحويلات اللاحقة. تُحد أحجام الردود ويُفحص الحجم والبصمة وتُزال الأجزاء الفاشلة. لا تُرسل جلسة Oriva أو Origin أو كلمة مرور أو رمز مزوّد، ولا يُعطّل فحص الشهادة. قد تؤجل إتاحة GitHub وحصص الطلبات المجهولة التحديث؛ لا تسمح بتثبيت غير موثّق.

يبقى المثبّت والمحدّث الحاليان مع فحص الملف المرحلي وحفظ الملف السابق والملف الشخصي واستعادة السابق إذا فشل التشغيل الفوري. ليس ذلك ضمانًا لاكتشاف انهيار متأخر بعد نجاح بدء العملية. يظل الملف غير موقّع؛ البصمات وHTTPS للمستودع حد الثقة بالتوزيع، وليسا توقيع ناشر مستقلًا.

تحتوي النسخة الداخلية1.5.3 والمرشحات القديمة عناوين Sites ثابتة. لا يمكن تحويل كودها تلقائيًا إلى GitHub دون تثبيت عميل جديد أو تعديل بيانات Sites القديمة. مسار الإطلاق الأول المدعوم هو تثبيت ZIP GitHub الموثّق يدويًا مع حفظ ملف المستخدم وجلسة DPAPI وترتيب التحديث؛ لا يستبدل تثبيت المالك تلقائيًا. تستخدم نسخ1.0.0 الجديدة GitHub بعد ذلك دون نشر Sites، والموقع يربط حاليًا صفحة إصدارات GitHub نفسها. رابط نسخة مباشر تحسين اختياري؛ لا يلزم تغيير Sites لتسليم تحديث العميل الجديد بعد نجاح قبوله الفعلي.

يُسجّل التنفيذ والاختبار الاصطناعي وفحص الشبكة والضيف الفعلي كلٌّ على حدة. لا تُعلن سلامة التسليم العام أو Stable قبل نجاحهما فعليًا.


تحقق30أكتوبر2026: نُشر Stable وLatest ونجح التنزيل العام وبصماته، وتثبيت ZIP والتحديث الفعلي بعميل QA أقدم وإعادة التشغيل واكتشاف Stable بالعميل المنشور. راجع [القبول الحالي](release-acceptance.ar.md).
